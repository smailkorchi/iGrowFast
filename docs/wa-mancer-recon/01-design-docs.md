## 0. System overview (docs/README.md)

SPEC architecture, one screen:

```
Browser (React/Vite SPA)
  → Supabase JS (auth + REST + Realtime WS)
  → Supabase (Postgres + Realtime + Edge Functions + Auth + Storage)
  → wa-mancer-worker (Node, Docker, Contabo VPS)  → Cloudflare R2 (media)
  → wa-mancer-evolution (Evolution API v2.3.7 + Baileys, Docker)
  → WhatsApp servers
```

Three load-bearing invariants:
1. **Supabase is the single source of truth.** Frontend never talks to worker or Evolution directly; worker writes to Supabase, frontend reads + Realtime.
2. **The worker is the outbound chokepoint.** Every send from any agent funnels through a per-instance serializer (humanized pacing). No code outside the dispatcher calls Evolution send endpoints.
3. **Evolution is wrapped, not exposed.** Only the worker and `instance-*` edge functions talk to Evolution; webhooks are secret-header-verified per request.

Doc index maps each subsystem to one file (foundation / numbers / inbox / operations / users / reference). `numbers-and-worker-plan.md` is explicitly historical (superseded by `numbers-pipeline.md`). `inbox-and-contacts.md` carries a banner that §2.2/§2.6/§2.8/§8.2 are stale vs current worker (raw SQL ingest, unified `contacts` table, outbound live, no profile-refresh TTL).

## 6. docs/database-design.md + supabase/README.md — foundation schema

Single-tenant, multi-instance. Entity map: `auth.users → profiles (1:1)`; `whatsapp_instances → conversations → messages`; `conversation_assignments` M:N users↔conversations; `audit_log` hash-chained.

**Tables (v1 spec):**
- `profiles`: id FK auth.users CASCADE, email citext UNIQUE, full_name, `role user_role ('admin'|'user')`, is_active, timestamps. Auto-provisioned by `AFTER INSERT ON auth.users` trigger.
- `audit_log`: bigserial, occurred_at (clock_timestamp), actor_uid, event_type, target_type, target_id, payload jsonb, prev_hash/this_hash bytea (SHA-256 chain, genesis 0x00…00). Chain serialized via `pg_advisory_xact_lock(hashtext('audit_log_chain'))`. Insert only via `audit()` DEFINER. `validate_audit_chain()` tamper check.
- `whatsapp_instances`: display_name, phone_number, evolution_instance_name UNIQUE, `evolution_api_token_ct bytea` (encrypted per-instance token), status enum `pending|connecting|connected|disconnected|error`, status_detail, qr_code, last_seen_at, created_by RESTRICT. Token write via `set_instance_token`; plaintext read only via `reveal_instance_token` (service_role).
- `conversations`: instance_id CASCADE, remote_jid (PLAINTEXT — deliberate: equality joins + webhook idempotency; RLS-mitigated), `is_group` GENERATED (`LIKE '%@g.us'`), peer_display_name, peer_profile_pic, last_message_at, `last_message_preview_ct bytea` (encrypted), unread_count, is_archived, is_pinned, UNIQUE(instance_id, remote_jid). Later + `status conversation_status DEFAULT 'open'`.
- `messages`: append-only; conversation_id + instance_id (denormalized for RLS speed), evolution_message_id, direction enum, kind enum (`text|image|video|audio|document|sticker|location|contact|reaction|system`), `body_ciphertext bytea` (encrypted), media_url, media_meta jsonb, reply_to_message_id self-FK SET NULL, sender_jid, whatsapp_timestamp, delivery_status, UNIQUE(instance_id, evolution_message_id) = webhook idempotency. Later additions: context_info jsonb, is_starred, is_forwarded, forward_score, media_pending, media_storage_key/_hash/_bytes/_mime (from media doc).
- `conversation_assignments`: (conversation_id, user_id) PK, assigned_by RESTRICT, assigned_at. THE authorization boundary.
- View `messages_decrypted`: security_invoker=true, exposes `body` via `_decrypt_message_body` (DEFINER wrapper — HARD RULE: never put `decrypt_text` directly in a view).

**RLS posture:** all public tables RLS on, default-deny; combined permissive policies per (role, action); every `auth.uid()` wrapped `(SELECT auth.uid())` for init-plan caching; direct DML on messages/audit_log revoked from authenticated — writes only via DEFINER fns.

**Function tiers:**
- public INVOKER (authenticated-callable): `is_admin()`, `has_role()`, `admin_assign_conversations`, `admin_unassign_conversations`, `audit()`, `set_instance_token`, `admin_set_user_role`, `admin_set_user_active` (last four are thin forwarders).
- `private` schema DEFINER (no PostgREST exposure): `private.audit`, `private.set_instance_token`, `private.admin_set_user_role`, `private.admin_set_user_active`.
- public DEFINER, EXECUTE revoked from anon/authenticated (service-role only): `_envelope_key()`, `encrypt_text`/`decrypt_text`, `ingest_message`, `reveal_instance_token`, `validate_audit_chain`, `bootstrap_admin` (idempotent one-shot first-admin promotion).
- Trigger-only: `_audit_log_hash`, `_on_auth_user_created`, `_on_profile_role_changed`, `_on_whatsapp_instance_change`, `_on_conversation_assignment_change`, `_set_updated_at`.
- Hardening invariant: all DEFINER fns `SET search_path = ''`, fully qualified refs.

**Encryption envelope:** Vault secret `wa_mancer_envelope_key` (32-byte random hex, pgsodium at rest). `pgp_sym_encrypt` (random IV, SHA-1 MDC). Encrypted columns: `whatsapp_instances.evolution_api_token_ct`, `conversations.last_message_preview_ct`, `messages.body_ciphertext` (+ later `webhook_secret_ct`). Tradeoffs section: remote_jid plaintext, media_meta plaintext, Vault-managed master acceptable interim → post-MVP external KMS with re-encrypt backfill.

**Migration index (supabase/README.md):** `20260517210001`…`210012` (init_extensions, audit_log, user_roles_and_profiles, vault_envelope_key, whatsapp_instances, conversations, messages, conversation_assignments, admin_management, advisor_remediation, revoke_anon_from_role_helpers, remove_definer_in_public).
